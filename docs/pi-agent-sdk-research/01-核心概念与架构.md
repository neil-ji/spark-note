## 1. 概述

pi 是一个极简的终端编码助手（minimal terminal coding harness），通过 TypeScript 扩展（Extensions）、技能（Skills）、提示模板（Prompt Templates）、主题（Themes）和 pi 包（Packages）进行扩展。底层 Agent 循环、会话管理、模型抽象均通过 npm 包 `@earendil-works/pi-coding-agent` 暴露为可编程 API。

**安装**：

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
# 或
curl -fsSL https://pi.dev/install.sh | sh
```

**运行模式**：

| 模式 | 命令 | 用途 |
|------|------|------|
| 交互模式 | `pi` | 完整 TUI，编辑器、聊天历史、全部内置命令 |
| 单次模式 | `pi -p "prompt"` | 发送提示、输出结果、退出 |
| RPC 模式 | `pi --mode rpc` | JSON-RPC 子进程集成（跨语言） |
| JSON 事件流 | `pi --mode json "prompt"` | 结构化事件 stdout 输出 |
| 无会话模式 | `pi --no-session` | 临时会话，不持久化 |

## 2. Agent 循环（Agent Loop）

pi 的 Agent 循环是基于事件的流式处理流水线，生命周期覆盖从用户输入到 agent 完全稳定的全过程：

```
用户输入
  → 扩展命令检查（/command 优先于普通输入）
  → input 事件（扩展可拦截/转换/处理）
  → before_agent_start（扩展可注入消息、改写系统提示词）
  → agent_start
    → turn_start
      → message_start → message_update (流式 delta) → message_end
      → tool_execution_start → tool_execution_update → tool_execution_end
    → turn_end
  → agent_end（含自动重试逻辑）
  → agent_settled（完全稳定：无排队续接、无重试）
```

### 2.1 关键行为

- **流式处理**：`message_update` 事件携带 `text_delta`（文本增量）、`thinking_delta`（思考增量）、`toolcall_delta` 等子类型
- **工具调用**：模型可调用内置工具（read/bash/edit/write/grep/find/ls）及通过扩展注册的自定义工具
- **转向（Steering）**：流式期间可通过 `steer()` / `followUp()` 排队消息，在当前工具调用完成后或 agent 完全停止后投递
- **自动重试**：瞬时错误（过载、限流、5xx）自动重试，通过 `auto_retry_start/end` 事件可观测
- **扩展命令优先级**：`/command` 格式的扩展命令即使在流式期间也立即执行，通过 `pi.sendMessage()` 管理自己的 LLM 交互
- **压缩重试**：溢出压缩后自动重试被中止的回合

### 2.2 事件类型总览

**SDK 层面（AgentSessionEvent）**：

| 事件 | 说明 |
|------|------|
| `agent_start` | Agent 会话开始处理 |
| `agent_end` | 一次低层运行结束（含 `messages` + `willRetry`） |
| `agent_settled` | 完全稳定（无重试/压缩重试/排队续接） |
| `turn_start` / `turn_end` | 一轮对话（assistant response + tool calls/results） |
| `message_start` / `message_update` / `message_end` | 消息生命周期 |
| `tool_execution_start` / `tool_execution_update` / `tool_execution_end` | 工具执行生命周期 |
| `queue_update` | 待处理 steering/followUp 队列变化 |
| `compaction_start` / `compaction_end` | 压缩过程（reason: manual/threshold/overflow） |
| `auto_retry_start` / `auto_retry_end` | 瞬时错误自动重试 |
| `summarization_retry_scheduled` / `summarization_retry_attempt_start` / `summarization_retry_finished` | 摘要重试 |

**扩展层面（ExtensionAPI 事件）**：

| 事件 | 时机 | 扩展能力 |
|------|------|---------|
| `project_trust` | 项目信任决策 | 返回 `{ trusted: "yes"\|"no"\|"undecided" }` |
| `resources_discover` | 资源发现 | 贡献 skill/prompt/theme 路径 |
| `session_start` | 会话启动 | reason: startup/reload/new/resume/fork |
| `session_shutdown` | 会话关闭 | 清理资源 |
| `session_before_switch` | 切换会话前 | 可取消 `{ cancel: true }` |
| `session_before_fork` | fork 前 | 可取消 |
| `session_before_compact` | 压缩前 | 可取消或提供自定义摘要 |
| `session_before_tree` | 树导航前 | 可取消或提供自定义分支摘要 |
| `before_agent_start` | agent 启动前 | 注入消息、改写系统提示词 |
| `input` | 用户输入 | 拦截/转换/处理（返回 action: continue/transform/handled） |
| `tool_call` | 工具调用前 | **可阻断**、可变参 |
| `tool_result` | 工具调用后 | 修改结果（中间件链式） |
| `context` | 发送给 LLM 前 | 修改消息列表 |
| `message_end` | 消息结束 | 替换最终消息 |
| `model_select` | 模型切换 | 可干预 |
| `before_provider_headers` | 发送请求前 | 增删 HTTP 头 |
| `before_provider_request` | 发送请求前 | 替换 provider payload |
| `after_provider_response` | 收到响应后 | 查看状态/头（流消费前） |

## 3. 会话（Sessions）—— JSONL 持久化与树形分支

### 3.1 存储位置与格式

会话以 JSONL 文件存储：

```
~/.pi/agent/sessions/--<path>--/<timestamp>_<uuid>.jsonl
```

`<path>` 为工作目录路径，`/` 替换为 `-`。例如 `/home/user/project` → `--home-user-project--`。

### 3.2 会话头（Session Header）

每个会话文件第一行：

```json
{"type":"session","version":3,"id":"uuid","timestamp":"2026-08-03T14:00:00.000Z","cwd":"/path/to/project"}
```

fork/clone 的会话额外包含 `parentSession` 字段指向原始会话文件路径。

### 3.3 条目类型（10 种）

| 类型 | type 字段 | 说明 |
|------|----------|------|
| 会话头 | `session` | 元数据（版本、ID、cwd），无 id/parentId |
| 消息 | `message` | 对话消息（含 User/Assistant/ToolResult/BashExecution/Custom/BranchSummary/CompactionSummary） |
| 模型变更 | `model_change` | 用户切换模型记录 |
| 思考级别变更 | `thinking_level_change` | 思考级别修改记录 |
| 压缩 | `compaction` | 上下文压缩记录（含 summary、tokensBefore、retainedTail） |
| 分支摘要 | `branch_summary` | /tree 导航时生成的分支摘要 |
| 自定义 | `custom` | 扩展持久化数据（**不参与 LLM 上下文**） |
| 自定义消息 | `custom_message` | 扩展注入消息（**参与 LLM 上下文**） |
| 标签 | `label` | 用户书签 |
| 会话信息 | `session_info` | 会话显示名称等元数据 |

### 3.4 消息类型（AgentMessage 联合类型）

```typescript
type AgentMessage =
  | UserMessage          // role: "user"; content: string | (TextContent | ImageContent)[]
  | AssistantMessage     // role: "assistant"; content: (TextContent | ThinkingContent | ToolCall)[]
  | ToolResultMessage    // role: "toolResult"; 含 toolCallId, isError
  | BashExecutionMessage // role: "bashExecution"; RPC 直接 bash 命令
  | CustomMessage        // role: "custom"; 扩展注入
  | BranchSummaryMessage // role: "branchSummary"; 分支摘要
  | CompactionSummaryMessage; // role: "compactionSummary"; 压缩摘要
```

### 3.5 树形分支

每个条目通过 `id`（8 字符 hex）/`parentId` 形成树，支持原地分支：

```
[user: "帮我写一个函数"]                          id: a1b2c3d4, parentId: null
  └─ [assistant: "好的，这是代码..."]              id: e5f6g7h8, parentId: a1b2c3d4
       ├─ [user: "能否用方案A优化？"]               id: i9j0k1l2, parentId: e5f6g7h8
       │    └─ [assistant: "方案A的实现..."]        id: m3n4o5p6, parentId: i9j0k1l2
       │         └─ [user: "完美"]  ← 活跃叶子     id: q7r8s9t0, parentId: m3n4o5p6
       └─ [user: "试试方案B"]                       id: u1v2w3x4, parentId: e5f6g7h8
            └─ [branch_summary: "方案A已完成"]      id: y5z6a7b8, parentId: u1v2w3x4
                 └─ [user: "用方案B重构"]  ← 替代分支
```

**分支操作**：

| 命令/API | 说明 |
|----------|------|
| `/tree` | 同文件内导航到任意历史点，创建新分支 |
| `/fork` | 从历史用户消息创建新会话文件 |
| `/clone` | 复制当前活跃分支到新会话文件 |
| `SessionManager.branch(entryId)` | 编程式分支 |
| `SessionManager.branchWithSummary(entryId, summary)` | 带摘要的分支 |

### 3.6 上下文构建

- `buildContextEntries()`：从叶子到根遍历，处理压缩条目（含 retainedTail）和分支摘要
- `buildSessionContext()`：转换为 LLM 消息列表，包括压缩摘要、分支摘要、自定义消息

## 4. 模型与 Provider（Models & Providers）

### 4.1 认证解析优先级

1. 运行时覆盖（`setRuntimeApiKey`，不持久化）
2. `auth.json` 中的存储凭据（API 密钥或 OAuth 令牌）
3. 环境变量（`ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 等）
4. 回退解析器（`models.json` 中的自定义 provider 密钥）

### 4.2 思考级别

`off` → `minimal` → `low` → `medium` → `high` → `xhigh` → `max`

后两个级别仅在支持扩展思考的模型上可用，非推理模型仅返回 `["off"]`。

### 4.3 自定义 Provider

```typescript
pi.registerProvider("my-provider", {
  baseUrl: "https://api.example.com/v1",
  apiKey: "$MY_API_KEY",  // 环境变量插值
  api: "openai",          // 或 "anthropic"
  headers: { "X-Custom": "value" },
  models: [
    { id: "my-model", name: "My Model", contextWindow: 128000, maxTokens: 4096 }
  ],
});
```

支持完整的 pi-ai `Provider` 对象，可覆盖原生 `auth`、`stream` 等方法。这为 MCP 桥接提供了关键的扩展点。

## 5. Extensions（扩展）

Extensions 是导出默认工厂函数的 TypeScript 模块，通过 [jiti](https://github.com/unjs/jiti) 加载（无需编译）。

### 5.1 加载位置

| 位置 | 作用域 | 热重载 |
|------|--------|--------|
| `~/.pi/agent/extensions/` | 全局 | ✅ `/reload` |
| `.pi/extensions/` | 项目级（需信任） | ✅ `/reload` |
| `settings.json` extensions 数组 | 自定义路径 | ❌ |
| `pi -e ./path.ts` | 临时加载 | ❌ |

### 5.2 核心 API

```typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";
import { StringEnum } from "@earendil-works/pi-ai";

export default function (pi: ExtensionAPI) {
  // 注册工具
  pi.registerTool({ name: "my_tool", /* ... */ });

  // 注册命令
  pi.registerCommand("mycommand", {
    description: "描述",
    handler: async (args, ctx) => { /* ... */ },
  });

  // 事件监听
  pi.on("tool_call", async (event, ctx) => { /* 可阻断 */ });
  pi.on("tool_result", async (event, ctx) => { /* 可修改 */ });
  pi.on("input", async (event, ctx) => { /* 可拦截/转换 */ });

  // 发送消息
  pi.sendMessage("content", { deliverAs: "steer" });
  pi.sendUserMessage("content", { deliverAs: "followUp" });

  // 会话控制（仅命令处理器可用）
  ctx.newSession({ /* ... */ });
  ctx.fork(entryId);
  ctx.waitForIdle();
}
```

### 5.3 自定义工具关键约束

- **StringEnum 必用**：字符串枚举必须使用 `StringEnum`，`Type.Union`/`Type.Literal` 与 Google API 不兼容
- **文件修改排队**：修改文件的工具必须使用 `withFileMutationQueue()` 包裹整个读-改-写窗口，与内置 edit/write 共享按文件串行队列
- **错误信号**：抛出错误标记 `isError: true`；正常返回永不设错误标志
- **terminate: true**：仅当批次内所有工具结果都返回 terminating 时才跳过后续 LLM 调用
- **嵌套 LLM 用量**：工具内部调用模型时，合并的 `Usage` 会计入会话统计

## 6. Skills（技能）—— 渐进式披露

Skills 是符合 [Agent Skills 标准](https://agentskills.io/specification) 的自包含能力包，采用"渐进式披露"（只有描述始终在上下文中，完整指令按需加载）。

### 6.1 格式

```markdown
---
name: my-skill
description: What this skill does and when to use it. Be specific.
license: MIT
compatibility: Node.js >= 18
allowed-tools: read bash
disable-model-invocation: false
---

# My Skill

## Setup
...

## Usage
...
```

### 6.2 加载位置（按优先级）

1. 全局 `~/.pi/agent/skills/`、`~/.agents/skills/`
2. 项目 `.pi/skills/`、`.agents/skills/`（需项目受信任，向上查找至 git 根）
3. 包的 `skills/` 目录
4. settings.json 的 `skills` 数组
5. CLI `--skill <path>`

### 6.3 触发流程

1. 启动时扫描 → 提取名称和描述
2. 系统提示包含可用技能（XML 格式，符合 Agent Skills 规范）
3. Agent 匹配任务时用 `read` 加载完整 SKILL.md
4. 也可通过 `/skill:name` 强制加载

## 7. Compaction（上下文压缩）与分支摘要

### 7.1 压缩触发

- **自动**：`contextTokens > contextWindow - reserveTokens`（默认 reserveTokens=16384）
- **手动**：`/compact [instructions]`

### 7.2 结构化摘要格式

```markdown
## Goal
[用户目标]

## Progress
### Done
- [x] 已完成
### In Progress
- [ ] 进行中

## Key Decisions
- **决策**: 理由

## Next Steps
1. 下一步

<read-files>path/to/file.ts</read-files>
<modified-files>path/to/changed.ts</modified-files>
```

### 7.3 分支摘要

`/tree` 导航时生成，保留离开分支的上下文。文件跟踪跨多次压缩/嵌套分支累计。

## 8. 关键架构约束（对 web 端智能体的影响）

1. **无内置沙箱**：pi 以用户权限运行，安全隔离依赖 OS/容器/VM 层面 → web 多用户部署必须自建容器隔离
2. **扩展与 pi 进程同地运行**：自定义扩展拥有完整系统权限 → 需严格控制扩展来源
3. **项目信任模型**：`.pi/` 下的资源配置仅在项目被信任后加载 → web 场景需设计自动化信任策略
4. **Node.js 生态**：仅支持 Node.js（≥18），TypeScript 通过 jiti 即时编译
5. **JSONL 持久化**：所有会话状态以 JSONL 行格式存储，支持原地分支 → 多用户需隔离会话目录
6. **无原生 MCP 支持**：文档中未提及 MCP，无相关链接或集成点 → 需自建桥接方案（详见文档 04）
