# 写作视角与认知框架(技术笔记体)

> L3-L5 分析产物。基于 37 篇技术文的选题、素材与价值取向归纳。

## 选题逻辑

- **动机分层(按占比排序)**:①面试备考(主旋律,tags 高频"前端进阶",jsmock 是"手撕代码"题库,js进阶 是问答式题库,reactcode 里"这里引申一个常见问题——setState 是异步还是同步的?");②知识体系沉淀(oop 三大特征→七大原则→23 模式全枚举、git 命令全集、内置对象 API 全列);③源码学习记录(React v17 源码系列,按调用链逐函数拆解);④工程实践/踩坑记录(filezilla 教程、覆盖式发布方案对比、虚拟列表/滚动加载实现);⑤自用需求→开源(github-heatmap);⑥随感(仅 daily 一篇)
- **体系化铺开**:基础知识(内置对象)→语言进阶(js进阶)→框架基础(react基础)→框架源码(reactcode)→工具链(webpack)→工程实践(fee),一个主题一篇;也有"想写就写"的痕迹("考虑单独去写一篇《Update Queue 机制》")
- 时间线:2023 年集中产出(面试/考研期,笔记体为主),2024-2025 转为讲解式(useReducer 的"先给路径再给代码"是 2025 年成熟写法)

## 素材策略

- **权威出处 + 亲历经验双轨**:官方规范英文原文(js进阶 引 ECMAScript Language Specification)、React 17 源码、W3C 标准(WCAG/WAI-ARIA)、LeetCode 原题;另一边是个人刷题心得("技巧总结：")、踩坑经历("当时少有中文资料,到处翻墙去找英文资料着实使我难受了一段时间")
- **自引闭环**:自己仓库与旧文互相引用("关于 React 源码解析可参考我的另一篇文章"、"详见我另一篇关于 React v17 源码解析的文章")
- 社区二手资料偶用(掘金/知乎博客、"讲的最好的协变、逆变"),但标注"参考这篇博客"
- 考研考点穿插("考研爱考,算法题没见过。")
- 例子类型:手写实现、双代码对照(React/Vue)、边界反例("root=[1,2], target = 1,根节点有一个左孩子,所以不算叶子节点,应当返回 false")、生活类比(大雁与雁群=聚合关系,翅膀与大雁=组合关系)

## 认知框架与价值观

- **实用主义与原理深挖并重**:一面"背诵要点"导向("递归实现只需记住返回结果时的规律"、"反着记");一面深挖机制("Promise 本质上是采用观察者模式"、三次握手/四次挥手问到底)
- **效率导向的取舍口吻**:"递归更为简单,但吃内存;迭代较为复杂,但一般效率较高;"
- **诚实记录不确定性**:不粉饰未完成与未知——"暂不清楚""遗留一个问题""鸽。。。下次补上""注:2、3实际应用场景暂不清楚"
- **笔记属性强于发表属性**:错别字、留空代码块、注编号不连续、`<!-- more -->` 迁移残留——这是"写给面试前的自己和未来的自己"的复习笔记,不是面向读者的成品文章;因此不写寒暄、不写过渡段、不追求完整收尾
- **开发者道德观**(仅 accessibility 结语流露):"分高低的不再是技术本身,而是境界"
- 隐含读者:**面试者 + 未来的自己**;文章兼有"给自己的笔记"与"给别人的讲解"双重身份(useReducer 前瞻给出 8 条前置概念清单,是"给读者设计学习路径"的表现)

## 文风演进(2023 → 2025)

- 2023:纯清单体、零第一人称、零衔接、戛然而止(笔记原样)
- 2024-2025:讲解式行文增多,出现"我推荐/我认为"、读者意识("吓退读者")、游戏化标题、"写在最后"——**新写文章应取 2024-2025 形态:清单骨架 + 少量讲解衔接**
