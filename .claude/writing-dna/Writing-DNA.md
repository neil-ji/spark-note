# Writing-DNA(Neil 技术笔记体)

> 整合文档。语料:37 篇技术文章(约 8.3 万字符,2023-2025),已足量(≥20 篇)。写作前请重读本文件及 语言DNA / 文章结构模板 / 写作视角与认知框架 / 视觉风格指南 四份分文档。

## 一句话风格

**清单体骨架 + 分号收尾条目 + "X:"定义式引导 + 注体系旁注,解释用"就是/也就是"改写,推理用"显然/可见"推进;零表格、零寒暄、零过渡段,多数文章无开头无结尾直接入题——写给"面试前的自己"的复习笔记,兼有给读者讲解的教学感。**

## 核心规则(可执行)

1. **条目分号收尾**:列表条目以全角";"收尾(57%)或干脆无标点,不用句号;一个条目平均 40 字,短条目为主
2. **"X:"定义式引导**:术语定义固定"X:全称(English)…;"格式;分组用"三大特征:""常见场景:""防御:"
3. **解释三板斧**:①"就是/也就是"直接改写("Provider,其实就是react内置组件Context.Provider")②"可看作/可理解为/可视为"("可看作useState和startTransition")③类比("原型链可以看作一个链表")
4. **推理推进词**:自问自答("为什么是三次握手?"→答案)、"显然/可见/综上/也就是说"承接推导
5. **注体系**:旁注一律进"注:"/"[注]:"/"注 1:",不写括号性说明;重点用"**重点一/二/三**"或"注意,"
6. **代码块注释即讲解**:代码紧跟文字解释,前有引导语("例子:"),注释极密集、可写完整推导,"// !!!"标核心逻辑
7. **零表格、零寒暄、零过渡段**:对照用"编号+加粗冒号引导+子 bullet",章节间标题硬切换
8. **加粗只给关键词/风险/结论**("**但有风险**")
9. **中英混排**:术语用英文不翻译,中英对照括号标配;标点允许半全角混用
10. **收尾三选一**:戛然而止 / 一句话轻收("…不再赘述。")/ 诚实标记未完成("鸽。。。下次补上""暂不清楚")

## 分体速查

| 文体 | 模板 |
|---|---|
| 算法题解 | 题目链接(带难度)→ 解题思路(编号推演/技巧总结：/细节：)→ 注 → JSDoc+中文注释代码 |
| 知识点清单 | 分节标题 → 定义bullet(分号收尾)→ 例子代码 → 注;无开头无结尾 |
| 概念讲解 | 前置知识/阅读指南开头 → 概念→原理→用法递进 → 讲解衔接语("我们先来看下这段代码")→ 完整代码 |
| VS 对比 | "X VS X"标题,双栏"编号+加粗冒号引导",或四段式(定义→优缺点→场景→实现) |
| 步骤教程 | H1 按操作顺序串,每节 1-2 句祈使指令 |
| 面试问答 | "## 什么是X?"/“为什么是X?"+ 计数式回答("三点：…") |
| 项目复盘 | 前言("起因是…")→ 思路 → 方案对比("对于X来说…")→ 实施 → 轻收尾 |

## 负面约束(去"AI 腔")

- ❌ 不用表格、不用"综上所述"式总结段、不写寒暄开头("欢迎阅读""随着技术发展")、不写过渡段
- ❌ 不用排比抒情、不用"首先…其次…最后…"三段式结构(语料中"首先…其次…"仅用于步骤清单,不用于篇章组织)
- ❌ 不用"值得注意的是""总而言之""举个例子"等书面 AI 高频词(语料用"注意,"/“例子:")
- ❌ 不追求完整收尾——没有结论就戛然而止,有未决问题就写"暂不清楚"
- ❌ 第一人称"我"低频出现(整篇 0-3 次),不出现"你";讲解感用"我们"
- ❌ 观点/结论必须真实——文风可以模仿,认知框架(实用主义+原理深挖+诚实记录)不可伪造

## 使用方式

写作前重读本文件 + 四份分文档;写完后对照"核心规则 10 条"逐项自检,特别是:条目是否分号收尾、定义是否"X:"引导、是否误用了表格/总结段/寒暄开头。
