# 文章结构模板(技术笔记体)

> L2 文章结构分析产物。37 篇技术文归纳出 8 种结构型 + 开头/结尾模式。

## 内容类型 A:算法题解(7 篇,模板最固定)

```
[题目链接外链,标题带难度:LeetCode Hard 32. 最长有效括号]
## 解题思路
  推演文字(编号列表 / "细节：" / "技巧总结：" / "考虑：" 引导,层层嵌套)
[注：...](偶发,夹在思路与代码之间)
```语言 代码块(JSDoc 头 + 极密集中文注释,注释即思路复述)
```

- 规律先行:"基本规律：二叉树前序遍历结果一定是`[root, left, right]`",规律之后才是印证代码
- 边界 case 单独强调:"本身很简单,但容易忽视**根到叶**这一特殊 Case:"后列反例
- 递进推演式写法(leetcode121 最典型):"1. 第一天买入,第二天卖出;2. 前两天的某天以**最低价**买入,第三天卖出;3. ..."
- 嵌套编号分情况讨论(leetcode32 最典型):编号可深达 4 层

## 内容类型 B:知识点清单/手册(多数笔记篇)

分节标题(常为概念名或问题)→ 一句话定义/要点 bullet → 例子代码块 → 注。**节间零衔接语,标题硬切换,多数无开头无结尾直接结束**。

- 并列式(css基础:20 个 ## 小节并列)
- 编号式(webpack:"1. Loader vs Plugin, 2. 常用 Loader…7. SPA 场景下的 HTTP 缓存策略")
- API 条目固定格式:"`assign(target, ...sources)`,复制sources的**自有可枚举属性**到target,并返回target;"

## 内容类型 C:概念讲解/教学(reactcode、useReducer、js进阶、redux)

先概念后原理后用法(redux:简介→标准Redux→异步方案→react-redux→RTK),讲解型文章才写衔接语:"讲完了`useReducerOnMount`和`useReducerOnUpdate`,引出我们的第一个问题…"、"我们先来看下这段代码"。useReducer 结构:"机制逐章 → # Final Boss:useReducerOnMount & useReducerOnUpdate → # 完整 Mock 代码"(游戏化标题、先给学习路径再给代码)。

## 内容类型 D:对比式(VS 类)

- "X VS X"标题模式:react基础 全篇"useEffect VS useLayoutEffect""useReducer VS useState""Props VS State";vue/index"Vue useComposable VS React Custom Hook"
- 双栏对比用"编号 + 加粗冒号引导 + 子 bullet"而非表格:"1. **状态定义** - Vue 使用`ref`或`reactive`… - React 使用`useState`…"
- 场景-方案四段式(覆盖式发布):定义 → 优缺点 → 适用场景 → 实现方式,每节 1-2 句

## 内容类型 E:步骤教程(filezilla)

H1 按操作顺序串:"下载与安装→添加磁盘访问权限→创建 FTP 服务器→配置 FTP 用户→本机测试→局域网访问",每节 1-2 句操作指令,祈使句隐含读者。

## 内容类型 F:问答式(面试题库:js进阶、html、protocols、浏览器内核)

每节一个问题+答案:"## 什么是原型链?""### 为什么是三次握手?"计数式回答:"三点：无需编写CSS就可以保持良好的文档结构、有助于SEO、有助于Web Accessibility;"(html 的"三点：/三层：/三点区别："是固定特征)。

## 内容类型 G:项目复盘(github-heatmap)

前言("起因是…")→ 思路 → 可行性分析 → 方案对比(平行段"对于稳定性来说,方案 1、2,都存在一个问题…"→ 结论) → 实施 → 代码讲解 → 轻收尾。唯一有"过程叙事感"的技术文。

## 内容类型 H:随笔(daily/2025-2-15,唯一一篇)

无标题无小标题,四段回环:场景白描 → 年少回忆 → 现实议论 → 回到当下收尾,首尾落在同一意象上("窗雨")。长流水句+完整主谓+拟人比喻,与技术文是两个完全独立的语体系统。

## 开头模式(按频率)

1. **无开头直接入题**(主流):首行即"## 数组类技巧"接"1. 滑动窗口;"
2. **定义直入**:首句下定义("Redux是一个集中存储和管理全局状态的库…")
3. **一句话动机/前言**:("数(据结构)算(法)再回顾,加深记忆抗遗忘。")
4. **题目/重点切入**:("题目要求只能在某一天买…"、"注释比较长,耐心看,**重点一**是看懂dp[i]表示的是什么…")
5. **阅读指南/前置知识**:useReducer 开头先列 8 条前置概念
6. **随笔场景**:("本文写于 25 年 1 月,杭州云谷,这两天气候干冷回暖,宜学习…")

## 结尾模式

- **无结尾,最后一条写完即止**(主流)——这是特征,不是缺陷
- **一句话轻收尾**:"界面比较易懂,不再赘述。"、"最后看一下`github-contribution`的项目依赖图,相对来说是比较小巧的。"
- **总结/升华**(罕见,离群):react_features 正式总结段;accessibility 全库唯一情感结语
- **未完成诚实标记**:"## scheduler 鸽。。。下次补上"
