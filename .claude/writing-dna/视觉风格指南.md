# 视觉风格指南(技术笔记体)

> L6 分析产物。纯 Markdown 技术笔记的排版体系(博客主题为 macOS Liquid Glass 风格,此处只记录语料内的 Markdown 排版 DNA)。

## 排版核心法则

1. **零表格**:全语料无一张表格。所有对应/对照关系用"编号 + 加粗冒号引导 + 子 bullet"承载("1. **状态定义** - Vue 使用… - React 使用…")
2. **条目分号收尾**:列表条目 57% 以全角分号";"收尾,28% 无标点,不做句号收尾
3. **"X:"定义式引导**:词条定义、分组标题、术语全称都用冒号引出("三大特征:""应用场景:""WCAG:全称**Web Content Accessibility Guidelines**…")
4. **"注"标注体系**(全库最高频元标注,四种写法并存):`注:`、`注 1:`~`注 5:`、`[注]:`、`[注 1]:`。注是唯一旁注手段,正文不写括号性说明
5. **加粗 = 关键词/风险/结论**,不用于整句强调("**但有风险**"、"**根到叶**")
6. **中英对照括号**:"中文(英文术语)"或"英文(中文)"("认证中心(Central Authentication Server)")

## 代码块规范

- 语言标注齐全(js/ts/html/css/json),位置永远在文字解释之后,前有引导语("例子:"、"我们先来看下这段代码"、"相当于")
- **注释即讲解**:代码注释极密集,常比代码还长,注释内可写完整推导("// 注意此处,x = i - 1,dp[x]已知" → "// 最后结果还要加上((...))之前的邻接合法子串长度,即dp[y-2]=dp[i-dp[i-1]-2]")
- "// !!!"标核心:"标记`!!!`的注释意为核心代码。"
- 中文标点可用在注释内(句号/分号混用)

## 标题与命名

- 正文标题层级以 `##` 为主,偶用 `###`;英文小节名允许("## Basic")
- 文章标题:中文无标点(react基础/Webpack 常识/JS手撕代码),或"X详解"(redux/react-router),或"难度+题号+题名"(LeetCode Hard 32. 最长有效括号),或系列"(一)(二)(三)"
- 文件名:snake_case 或拼音缩写(reactcode17.0.2/useReducer/virtuallist/jsmock)
- frontmatter 规范:title / description('' 留空)/ pubDate(格式 2023-04-19 13:57:58)/ tags(数组,含"前端进阶")

## 图片

- 图片引用格式:Markdown 标准 `![说明](路径)`,说明文字简短

## 允许的不完美(风格的一部分)

错别字、留空代码块、注编号不连续、半全角混用——**刻意写出的"完美"反而脱离文风**;写作时保留 1-2 处自然的笔误级痕迹是还原度的一部分(但用户明确要求的正式发布文除外)。
