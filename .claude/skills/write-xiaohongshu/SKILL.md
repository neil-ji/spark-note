# 小红书通用写作

产出适合小红书平台的内容。核心交付物：

1. **纯文本稿件**（必须）— 无 Markdown 格式，可直接粘贴到小红书编辑器
2. **HTML 卡片**（可选）— 用于生成高质量图文卡片
3. **PNG 截图**（可选）— 从 HTML 自动生成

## 写作规范

### 内容结构

```
[标题] — 有吸引力、有信息量，15 字以内最佳

[正文]
- 开篇钩子：一句话抓住读者，提出问题或制造反差
- 主体内容：2-4 个要点，每个要点用短段落，配恰当比喻
- 总结收尾：一句话点题 + 互动引导（关注/评论/收藏）

[标签] — 3-5 个话题标签，如 #AI科普 #效率工具
```

### 语气原则

- **介于严肃与轻松之间** — 不说教、不卖弄、不讨好
- **像朋友聊天** — 用「你」而非「大家」，用「我试过」而非「建议」
- **用比喻代替术语** — 「像图书管理员」优于「基于 transformer 架构的」
- **信息密度适中** — 5 分钟内可读完，约 800-1200 字

### 文风防漂移（通用版，所有小红书文稿适用）

以下锚点从 `tingguo-weekly` 文风机制中提取并通用化。用于所有小红书写作，与具体作者文风无关。

#### 标点规范（平台硬约定）

- **引号**：强调/自创概念用 `「」`（直角引号），不用 `""`、`''`
- **破折号**：用 `——`（两个全角），不用 `—`、`--`
- **分隔**：段落间空一行，不用 `———` 分隔线
- **禁止 Markdown 标记**：无 `**`、`##`、`- `、`1. `。强调靠「」引号，层级靠空行和自然分段

#### 比喻守则

技术科普类内容的核心武器是比喻，但比喻失控反而是噪音：

- **一个概念只用一个比喻**。如 Agent = 助理，不要同时又说 Agent = 自动驾驶
- **比喻必须来自日常生活**（图书管理员、助理、实习生、字典、USB 插头），不来自技术域
- **先用比喻讲清楚，再给技术名**。「像一个图书管理员…这就是所谓的 RAG。」

#### 禁止 AI 味过渡词（写完后全文搜索删除）

以下词汇一旦出现，立刻删除或改写：

| AI 味 | 改法 |
|--------|------|
| 在当今时代、随着…的发展 | 直接删掉，从第二句开始 |
| 综上所述、总而言之 | 删掉，前面那句话就是结论 |
| 值得注意的是、值得一提的是 | 删掉，不值得注意就不会写 |
| 此外、另外、不仅如此 | 换自然转折：`还有`、`更关键的是` |
| 我们可以看出、不难发现 | 删掉，让事实自己说话 |
| 极大地、显著地、有效地 | 删掉副词，或者给具体数字 |

#### 结构模板（按内容类型选择）

**模板 A：问题-答案型**（适合解释一个概念）

```
[标题] — 提问式或反差式

[钩子] 你大概率遇到过 XX 场景…但如果告诉你 YY 呢？

[是什么] 用比喻讲清楚概念，200 字以内

[为什么] 为什么会这样 / 为什么是现在，1-2 个原因

[跟你的关系] 这事对你意味着什么，你能怎么用

[收束] 一句话点题 + 互动引导

[标签]
```

**模板 B：叙事型**（适合分享经验/踩坑）

```
[标题] — 结果导向，制造好奇

[背景] 我遇到了什么问题 / 想达成什么

[过程] 试了 A，不行；试了 B，差一点；最后发现 C。给具体细节

[关键认知] 这件事教会了我什么（1 个核心 insight，不要 3 个）

[对你有什么用] 读者如何复用这个认知

[收束 + 标签]
```

**模板 C：清单型**（适合推荐/对比）

```
[标题] — 数字 + 主题，如「3 个你可能用错的 AI 工具」

[开篇] 一句话说明为什么值得看

[逐条展开] 每条 80-150 字，结构：名称 → 一句话定义 → 适用场景 → 注意事项

[总结] 帮你选（按需求分类推荐）

[互动 + 标签]
```

#### 完稿自检清单（每次写完逐项勾验）

- [ ] 标题是否在 15 字以内且非标题党？
- [ ] 开篇是否在第一句就抓住读者（制造反差/提出问题/具体场景）？
- [ ] 每个抽象概念是否都配了一个生活化比喻？
- [ ] 全文搜索「在当今」「综上所述」「值得注意的是」「极大地」——是否全部删除或改写？
- [ ] 是否有两段之间感觉突兀的跳跃？（如果有，加一句过渡）
- [ ] 是否**没有任何** Markdown 标记（`**`、`##`、`- `）？
- [ ] 是否**没有任何**英文引号 `""` `''`？（中文内容全用 `「」`）
- [ ] 是否至少有一个自己亲身经历的细节（不是泛泛的「很多人都会…」）？
- [ ] 收尾是否有明确的互动引导（关注/评论/收藏/试试）？
- [ ] 全文是否在 800-1200 字之间？
- [ ] 标签是否是 3-5 个具体话题（不是 #生活 #日常 这种泛标签）？

**任何一项未通过 → 修改文稿，不进入下一步。**

## 稿件产出流程（文稿优先，HTML 在后）

**核心原则：纯文稿件是第一产物，手工编写；HTML 是视觉呈现，从文稿派生。**

### Step 1: 明确选题和角度

向用户确认：
- 目标读者是谁（技术人 / 非技术人 / 混合）
- 核心信息是什么（一句话概括）
- 期望读者看完后记住什么

### Step 2: 撰写纯文本稿件（先做这一步）

**手工编写**，不使用任何 Markdown 语法。段落间用空行分隔。这是小红书发布的原始素材，必须是干净的人读文本——标题 + 正文 + 话题标签，不含任何 UI 标签或格式标记。

将稿件保存到用户指定的位置，默认建议：
```
content/其他/<主题-slug>/manuscript.txt
```

### Step 3: 生成 HTML 卡片（从文稿派生）

以文稿内容为基础，参考下方的 HTML 模板规范生成视觉卡片。HTML 是文稿的视觉包装，不是文稿的来源。

### Step 4: 生成 PNG 截图

使用 `tingguo-weekly` 的截图工具：

```bash
node .claude/skills/tingguo-weekly/tools/screenshot.mjs <html-file> <output-dir>
```

### 附：从 HTML 恢复文稿（仅作应急）

如果 HTML 还在但原始文稿丢失，可尝试从 HTML 提取（会跳过 UI 装饰，但效果不如手工文稿）：

```bash
node .claude/skills/tingguo-weekly/tools/extract-text.mjs <html-file> [output-file]
```

## HTML 卡片制作规范

### 布局结构

使用卡片叠层（card deck）布局：750px 宽 × 960px 高的独立卡片，垂直排列。

```html
<div class="deck">
  <div class="card cover">   <!-- 封面页，带 .cover class -->
  <div class="card">         <!-- 内容页 2 -->
  <div class="card">         <!-- 内容页 3 -->
  <div class="card">         <!-- 内容页 4 -->
  <div class="card">         <!-- 内容页 5（总结） -->
</div>
```

### 封面页组件

```html
<div class="card cover">
  <div class="cover-blob cover-blob--a"></div>   <!-- 装饰色块 -->
  <div class="cover-content">
    <div class="cover-eyebrow">分类 · 日期</div>
    <h1>标题：<em>重点高亮词</em></h1>
    <p class="cover-sub">副标题说明</p>
    <div class="cover-meta">
      <span>阅读时间</span>
      <span>标签</span>
    </div>
  </div>
</div>
```

### 内容页通用组件

| 组件 | CSS class | 用途 |
|------|-----------|------|
| 页面头 | `.page-header` + `.page-kicker` + `h2` | 每页的主题标签 + 标题 |
| 洞察框 | `.c-insight` | 核心观点高亮展示 |
| 对比表 | `.c-compare` | 左右两栏对比 |
| 引用金句 | `.c-hl` | 一句话金句强调 |
| 公式条 | `.c-formula` | 流程/公式展示 |
| 要点行 | `.c-bullet-row` | 要点列表 |
| 结论卡 | `.c-takeaway` | 编号结论 |
| 标签组 | `.c-tag-strip` | 末尾关键词标签 |
| 页脚点 | `.page-footer-dots` | 翻页进度点 |

### 默认颜色变量

```css
--bg:        #faf7f2;    /* 暖纸底色 */
--surface:   #ffffff;    /* 卡片白 */
--text:      #2c2416;    /* 暖黑主文字 */
--text-2:    #6b5e4f;    /* 次要文字 */
--text-3:    #9b8e7f;    /* 辅助文字 */
--accent-1:  #c1664b;    /* 主强调色 */
--accent-2:  #4a8c7c;    /* 副强调色 */
--border:    #e8e0d5;    /* 暖色边框 */
```

### 必须遵守的设计规则

1. 所有间距用 `--space-*` token，不写硬编码 px
2. 一个卡片最多使用 2 种强调色（`.c-*-brand` + `.c-*-teal`）
3. 每页控制在 750px × 960px 可视范围内
4. 5 张卡片是标准配置：封面 + 3 个内容页 + 总结页
