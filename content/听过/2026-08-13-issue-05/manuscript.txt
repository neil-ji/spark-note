《听过第五期》MCP：AI 的「通用插头」

这是《听过》系列的第五期。第二期聊了 AI Agent——让 AI 不止会聊天，能自己动手干活；但「干活」怎么接上外部工具？这期聊那根「通用插头」——MCP。

MCP:全称 Model Context Protocol（模型上下文协议），2024 年底由 Anthropic 开源的一套标准；一句话概括——AI 的「通用插头」；AI 想干活，先问工具，MCP 就是「问」的规矩。

可看作:USB-C。没有统一插头之前，每台设备配一根专属线，出门带一包；没有 MCP 之前，AI 每接一个工具就要专门写一套对接代码，一对一，接一个写一个，工具一多就失控；有了 MCP，工具厂商按标准做一个接口，AI 拔插即用——一对多。

也就是:工具是「插座」，MCP 是「插座标准」；AI 不用关心插座背后是 GitHub 还是数据库，只要符合标准，插上就能用。

MCP 的架构是三件套:Host（宿主，也就是承载 AI 的应用，比如我们正在对话的这个）、Client（客户端，藏在 Host 里的连接器）、Server（服务端，每个外部工具提供一个）；干活流程:AI 想干活 → Host → Client → 找到对应 Server → Server 递上「能力清单」，列明有哪些工具、怎么调 → AI 照单调用，干完即止。

可见:分工清晰——Server 负责描述能力，AI 负责决策调用；协议只定义「怎么接」，不规定「接什么」，所以工具可以无限扩充。

实践层面:让 AI 查 GitHub 趋势、订机票、读写本地文件、连数据库，背后基本都是 MCP 在干活；主流模型与各厂已原生支持，开源标准，生态还在快速长。

MCP 的意义不在某个具体工具，而在「标准化」三个字——AI 与工具世界之间从此有了一层通用接口；可以想见，未来 AI 的能力边界，越来越多由插头的数量决定，而不是模型本身。

听过，比学会更重要。
