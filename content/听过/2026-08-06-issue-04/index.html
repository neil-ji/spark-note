Token 与上下文窗口：AI 的「记忆力」

介于严肃原理与轻松科普之间

听过 · 第四期
核心概念
定义

AI 的「记忆力」：
由两个数字决定

Token 是单位，上下文窗口是容量
Token

AI 读文本的最小单位，就是把一句话切碎成的小块。英文里一个单词约等于一个 token， 中文一个字约一到两个 token。粗略估算，100 个英文 token 大约对应 75 个单词。

上下文窗口 Context Window

AI 一次能「同时看到」的 token 总数，也就是单次对话里眼前能摊开的所有内容。 窗口以内的看得到、能引用；窗口以外的——哪怕五分钟前刚聊过——一概不记得。

Token 是 AI 认识世界的「字」。 上下文窗口是 AI 一次能摆在桌上的「字」的总数——窗口的大小，就是它工作记忆的大小。

上下文窗口

像一张书桌。AI 工作时的「眼前」，能摊开的资料就这么多。

书桌就这么大，一次摊开的有限。

RAG

像一座图书馆。第一期讲过，RAG 让 AI 学会临时去查资料。

但查回来的内容，必须搬上书桌（塞进窗口），AI 才用得动。

窗口大小，决定 AI 一次能读多厚的材料。
Claude 的窗口做到 1M token，约 75 万英文单词，可一次读完《三体》三部曲；常见模型是 128K 左右，大概一本几百页的书。

书桌就这么大，一次摊开的有限。 想读更多，要么换更大的桌子，要么像 RAG 一样——按需去查，查完用完就收。

实用提醒
计价与提醒

窗口越大越贵，
聊得越长越容易「忘」

显然

token 同时是 AI 的计价单位。API 按输入输出 token 收费， 窗口每多塞一个字，成本就多一分；从 128K 涨到 1M，单次调用成本能差好几倍。

长对话靠把整段历史塞进窗口维持「记忆」——聊得越长窗口越满，越容易在细节上犯错；重要内容放回对话末尾，或直接开新对话
遇到「AI 忘了之前的结论」，多半不是它蠢，而是内容已超出窗口
历史对话 → 塞满窗口 → 超出部分 → 彻底遗忘
听过 · 第四期
小结

你可以不精通，
但应当「听过」

1

窗口是工作记忆，不是长期记忆

Token 是单位，上下文窗口是容量。窗口以内看得到、能引用，窗口以外一概不记得。 技术圈每年在卷窗口，从 4K 卷到 1M——但本质没变：它只是一次性摊开的书桌，不是书架。

2

RAG 负责长期，窗口负责当下

真正长久的记忆，靠的是 RAG 那套——查资料，而不是背下来。 书桌有限没关系，学会随时去图书馆搬，用完就收。

3

「忘」了不怪 AI，怪窗口

长对话容易在细节上犯错，是窗口被历史塞满的必然结果。重要信息放回对话末尾，或直接开新对话—— 给 AI 换张干净的桌子，比什么都管用。
